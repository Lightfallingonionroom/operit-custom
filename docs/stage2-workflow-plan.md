# 下一阶段方案：工作流模板层

依据 `docs/ref-fujiang-gpt6.md`。目标：把「6 模板 + 80 叶子三拍 + 口语归一」变成 Operit
可开关的定制能力，与现有 square/Purge/ZFX 三层互补。

---

## 一、要复刻的三层

### 层 1：六模板入口

| 模板 id | 显示名 | 绑定能力 |
|---|---|---|
| `web` | 网站与接口检查 | pentest 类 skill / 工具包 |
| `api` | API 与身份权限 | API 安全类 |
| `chain` | 渗透任务编排 | 编排类 |
| `reverse` | 逆向与样本分析 | `rea` 包（Operit 已内置） |
| `audit` | 源码审计 | 代码类 |
| `report` | 证据整理与报告 | 文档类 |

### 层 2：80 条叶子三拍

```
第一步 取料   拿靶标、文件、参数
第二步 处理   分类处理（含分支，如「有壳先脱壳」）
第三步 交付   产物 + 检查点 + 回滚 + 收口行
```

收口行固定：`当前:对象 / 结果 / 下一步`

六类父技能与叶子数：
bin-unlock 17 / playfield 13 / netcast 15 / apicloud 13 / labpipe 11 / inkstage 11 = 80。

### 层 3：口语归一

```
第一步 洗口   去掉空转词；同音纠错（卸锁=解锁 唾壳=脱壳 视透=透视 自喵=自瞄 主入=注入）
第二步 对照   口头禅 → 叶子（更长碎片优先，同长取靠前）
第三步 开跑   命中即执行，缺参用占位符填满；禁止把路由过程说出口
```

零分兜底：有二进制 → 逆向；有 HOST/IP/URL → 渗透；纯文字 → 内容创作。

## 二、落地形态（需拍板）

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| **A. 提示词注入** | 三拍 + 归一表写成注入文本 | 改动小、一次构建 | 每轮占 token；80 条全量过重 |
| **B. 复用 skill 包** | 三拍做成 Operit skill 包按需加载 | token 省、贴合架构 | 需做包 + 面板 |
| **C. 混合** | 只注入归一规则 + 六模板入口；叶子按需调起 | 平衡 | 实现量中等 |

推荐 **C**：归一规则（约 4KB）注入管「听懂话」，六模板做面板入口管「快速开跑」，
叶子按需调起管「做对事」。
